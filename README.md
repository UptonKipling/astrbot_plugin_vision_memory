# 首次部署教程（图文）

> 本节整合自《识图插件部署教程》，适用于第一次安装本插件的场景。

## 1. 关于依赖安装

插件第一次部署时会自动下载部分依赖，但 **CCIP 需要手动在你的电脑上部署**。

## 2. 手动安装 CCIP 依赖（dghs-imgutils）

1. 打开你的 AstrBot 的**日志界面**。
2. 点击左上角的**安装 pip 库**，在库名处输入：

   ```
   dghs-imgutils==0.19.0
   ```

   然后点击安装。

   ![](docs/images/image1.png)

3. 下载的依赖会有点多，**消耗时间较长**。哪怕出现类似下图的界面消失，也不一定代表已经装好：

   ![](docs/images/image2.png)

4. **当完全装好时，日志中会出现类似于“安装完成”的提示**，此时再开始配置插件。

5. 如果你后续使用中发现 CCIP 没装上，可以把下面的网址喂给 AI，让它教你安装：

   ```
   https://dghs-imgutils.deepghs.org/main/api_doc/metrics/ccip.html
   ```

   ![](docs/images/image3.png)

## 3. 插件配置与魔裁图库构建

打开 AstrBot 的 WebUI 配置界面，根据视频和参考图完成**魔裁图库的人工构建**：

![](docs/images/image4.png)

注意事项：

- 正常上传图片时，应显示 **“视觉”和“CCIP”均为打勾状态**；偶尔“视觉”没有识别上是正常现象。
- 插件配置界面一般不用改动，把 **“识别自己‘夏目安安’”** 那一栏改成你自己家 Bot 的名字即可。
- 插件能实现的其他功能，见本 README 后续章节与 `SKILL.md`。

# v1.8.0 行为变更（重要）

**从 v1.8.0 开始，Bot 图片库彻底取消“上下文自动命名/自动入库”。** 这是对早期版本上下文学习逻辑的硬切换，下面旧版本章节中关于“用户/群友后续说出名称即可自动入库”的描述仅用于历史说明，**不再适用于 v1.8.0**。

- 未达到任何库接受阈值的图片：原图永久保存到 **“待管理员命名”**。
- 插件不会读取聊天上下文来给图片起名。
- 插件不会根据用户后续消息自动把图片绑定到名称。
- 插件不会根据 Bot 自己的回复学习名称。
- 不会因为群友插话、上下文压缩、LLM 历史等因素自动创建 Bot 图片库栏目。
- 管理员在 WebUI 查看待命名原图，手动输入名称后，才会正式加入 **Bot 图片库**。
- 待命名图片默认永久保留，管理员可以手动“命名并入库”或“删除”。
- 群聊识图仍要求当前消息存在真实的 @Bot；引用消息/历史消息里的 @ 不算当前消息 @。

因此，v1.8 的 Bot 图片库原则非常简单：**Bot 只负责保存未知图片，名字永远由管理员决定。**

# 魔裁视觉识图与三库记忆（UptonKipling）

## 1.0.1 修复说明

本版本重点修复 AstrBot 4.27.x Plugin Page 的图片上传问题。

### 根因
AstrBot 的 `window.AstrBotPluginPage.upload()` 要求 endpoint 是插件内相对路径，并且**不能包含 query string**。旧版页面调用：

`upload?library=...&entry_id=...`

会被 bridge 在 iframe 内直接拒绝，因此后端 `web_upload()` 根本收不到图片。旧版随后又调用浏览器 `alert()` 报错；AstrBot Plugin Page 运行在受限 iframe 中，没有 `allow-modals`，所以控制台进一步出现 `Ignored call to 'alert()'`。

### 修复
- 上传改为：`upload/<library>/<entry_id>`。
- 后端改为动态路由参数读取 library / entry_id。
- 删除 `alert()` / `confirm()`，改为页面内提示与确认框。
- 上传前检查图片格式和 20 MB 大小限制。
- 上传成功后自动刷新栏目并自动提取识别关键特征。

其余识图、三库、阈值、夏目安安自身判定、Bot 图片库 7 天遗忘、日志等功能保持不变。

## 安装

将压缩包直接放入 AstrBot 的插件安装界面安装，或解压到 `data/plugins/astrbot_plugin_vision_memory/` 后重新加载插件。

如果你已经安装旧版，建议先在 AstrBot 插件管理里停用/删除旧版，再安装本版本，避免旧文件残留。插件运行数据位于 AstrBot 的插件数据目录，不在压缩包内，因此删除插件源码通常不会自动删除已有图片库数据。


## 1.3.0 重要行为

- **AstrBot 4.27.x 兼容修复**：`TextPart` 使用 `TextPart(text=...)` 创建，绝不把裸字符串写入 `req.extra_user_content_parts`，避免 `agent_sub_stages.internal` 中出现 `str.model_dump()` 错误。
- **魔裁二创识别增强**：默认人物阈值调整为 42%，模型提示明确允许同人图、截图、不同画师、换装、表情、角度和姿势变化，身份判断以脸部/五官/发型/稳定视觉特征为主。
- **管理员手动命名式 Bot 图片库**：识别失败的图片只进入临时待确认区，不会直接污染 Bot 图片库；如果之后用户或 Bot 明确说出“图片里是 XX”等身份信息，插件才会正式保存这张图。
- **WebUI 图片预览**：通过 Plugin Page Bridge 读取图片数据，直接在管理页面显示已上传参考图。
- **单图删除**：每张参考图都有独立删除按钮，删除图片不会删除人物/事物栏目。


## v1.3.0 上下文学习增强

- 三个图片库统一采用二创友好的鲁棒视觉身份匹配，不要求立绘/参考图完全一致。
- 普通人物/事物与 Bot 图片库默认阈值调整为 45%。
- 未知图片进入持久化“待确认队列”，不会自动命名或直接污染 Bot 图片库。
- 群聊待确认队列按群共享，不再只绑定发图者，因此其他群友也能完成身份确认。
- 同一会话允许同时保留多张未知图片，并支持“上一张 / 第1张”等自然指代。
- 当前 LLM prompt、普通消息事件和 Bot 后续回复三条链路共同捕获明确身份确认，以降低长上下文/插话导致的漏记忆。
- 确认后的名称以人类明确给出的名称为准，不再让视觉模型自行猜测 Bot 图片库名称。
- WebUI 增加待确认图片页面，可直接预览、手动确认入库或删除。


## 1.3.0 核心修复

### 为什么之前会出现奇怪的名称
旧版本的上下文学习会把 Bot 的普通回答也当成“身份确认”候选；同时特征解析函数缺失，导致参考图特征长期显示为提取失败。结果就是 Bot 图片库可能出现“不起……”“片中的人物叫做洛茜”等句子型栏目名。

### 现在的入库原则
1. 未知图片先进入持久化待确认队列，不自动命名。
2. 用户/群友的明确身份说明才是权威，例如“这个角色叫做洛茜”“这张图是小明”“刚才那张就是洛茜”。
3. Bot 自己的回复不会单独创造身份名称。
4. 插件独立记录近期会话文本，和 AstrBot 的上下文压缩解耦；中间插话不会丢失待确认图片与后续说明的关系。
5. 多张待确认图无法确定指代时宁可等待，不会把名字绑定到错误图片。

## 1.7.0 重要修复

- **显式纠错覆盖识别**：如果模型先把图片认成 A，用户随后明确说“认错了，这张是 B / 这个角色叫 B”，B 会直接成为权威身份并写入 Bot 图片库；不会因为原先 A 已超过阈值而阻止纠正。
- **近期图片账本**：插件独立保存近期图片与会话关系，不依赖 AstrBot 当前 LLM 历史，因此群聊插话、上下文压缩后仍能解析“刚才那张/上一张”。
- **真实参考图二阶段核验**：候选排序后，使用候选库实际参考图片进行再次视觉核验，降低“同发色误判”为同一人物的问题。
- **特征解析器修复**：统一兼容纯文本、JSON、Markdown fenced JSON 等视觉模型输出格式，并在启动时执行解析器自检。
- **三个库统一二创友好**：魔裁人物库 42%，人物事物添加库与 Bot 图片库 45%；换画师、Q版、截图、换装、姿势变化不要求与原立绘像素一致。


### v1.7.0 重要修复
- 修复 `_attach_context_copy` 缺失导致的识图时报错。
- 通过 `get_sender_id() == get_self_id()` 优先判断 Bot 自己的消息，禁止 Bot 输出图片进入上下文学习/记忆。
